# Skyfall: fine-tune a Kev decision model to fly a stick man

Demo plan for a 30-minute talk. Written 2026-09-30, demo week of 2026-10-05.
Principle: smallest game that still reads as skydiving, one rule a 0.8B model
can recover from text, and only one comparison: Kev before vs after our fine-tune.

---

## 1. The game (rules frozen 2026-09-30, implemented in `game/`)

**World.** A 5-column by 6-row grid. Row 0 is the top. The skydiver `Y` sits
at row 1 and never moves vertically. Obstacles scroll **up** one row per tick:
that is how falling is drawn. Altitude starts at 3000 m and drops 100 m per
tick, so a jump lasts at most 30 ticks.

**Obstacles.** One cell each, at most one deadly obstacle per row, spawned at
the bottom row with probability 0.6 per tick. Clouds spawn independently
(probability 0.3 per row) and are harmless: you fly straight through them.
The model has to learn which letters kill and which do not.

| Symbol | Meaning |
|---|---|
| `B` | bird, deadly |
| `P` | another skydiver under their parachute, deadly |
| `A` | airplane, deadly |
| `C` | cloud, **harmless** |
| `O` | hot-air balloon, deadly. **Never in training data.** Added at demo time with `--surprise`. |

**Actions, every tick.**
- `move`: `left`, `right` or `stay`. One column, clamped to the grid.
- `open`: `true` / `false`. Pull the parachute.

**Win / lose.**
- Lose if a deadly obstacle reaches your cell. Clouds do nothing.
- Lose if altitude reaches 0 without opening.
- Lose if you open above 1000 m.
- Lose if you open while the cell directly below you holds something deadly.
- Win if you open at or below 1000 m with the cell below clear (empty or cloud).

**What the model sees** (the state, 43 tokens with the Kev tokenizer):

```
altitude: 2200
. . . . .
. . Y B .
. . B . .
. . . . B
. . P . .
A . . . .
```

**The rule it has to learn** (the oracle, `game/oracle.py`, 15 lines):
1. If the cell below you is clear (empty or cloud), stay.
2. Otherwise step sideways, toward the centre first (from the centre column,
   right first), into a column whose current cell and cell below are both
   clear. If neither side is clear, stay.
3. Open only at or below 1000 m, and only when the cell directly below you
   is already clear. If something is below you, sidestep this tick and open
   on a later one. (Each question is a pure function of the state, matching
   how Kev answers questions: independently of each other.)

Measured on the final layouts (with clouds): oracle wins 94% of 500 seeded
jumps, random policy 0.0%. With the surprise balloon, on identical layouts,
the oracle still wins 94%, because it treats any letter other than `C` as an
obstacle. The question for the demo is whether the fine-tuned model does too.
(The oracle has no lookahead; a player that looked further ahead could reach
about 97%. 94% is the rule's ceiling, and the rule is what the model imitates.)

**Two questions per state** (`data/questions.py`):
- `move`: choice over `left`, `right`, `stay`.
- `open`: noul.

## 2. Decisions

| Decision | Choice | Why |
|---|---|---|
| Model code | `jaredpalmer/kev` repo as-is: `kev.train`, `kev.benchmark`, `kev.serve` | One week. Don't reimplement LoRA + pointer head, explain it on one slide. |
| Model | `jaredpalmer/kev-0.8b` as `--init_from`. 4B only if 0.8B fails. | 20 min on H100, fits an L4. |
| GPU | Colab Pro, L4 or A100 | Kev trains in bf16. Free-tier T4 has no bf16. |
| Comparison | Released Kev-0.8B vs our fine-tuned Kev-0.8B. Oracle shown as the ceiling. | That's the whole claim: fine-tuning mattered. No LLM, no classic classifier baselines. |
| Twist | Balloon `O` at test time | The question text says "clouds are harmless, any other letter is deadly". Does the model apply that to a letter it never saw, or did it memorise B/P/A? |
| Optional closer | Latency per decision, Kev vs a general LLM asked the same question | Only if everything else works. Shows why the architecture exists. |
| Data | 20k train / 2k eval, generated by `data/generate.py`, mixed 40% dodge / 15% open / 5% low-altitude-but-blocked / 40% idle | Oracle labels are ground truth. Balanced so the model can't win by always saying `stay`. |

Prior art to cite: [mittal-parth/jev-experiments](https://github.com/mittal-parth/jev-experiments)
drives Chrome's dino game with hosted Jev zero-shot through the SDK, no
fine-tune, no numbers. We do the local fine-tuned version.

## 3. Measurements

Two rows, same eval file and same 200 seeded jumps:

| | `move` acc | `open` acc | Brier | win rate | win rate with `O` |
|---|---|---|---|---|---|
| Kev-0.8B released, zero-shot | | | | | |
| Kev-0.8B fine-tuned on Skyfall | | | | | |
| Oracle (the rule) | 1.00 | 1.00 | 0 | 0.94 | 0.94 |

Success bar before the demo: fine-tuned `move` >= 90%, `open` >= 95%, win
rate >= 60%. If base Kev already wins more than 20% of jumps, raise spawn
probability and regenerate.

## 4. Day-by-day

**Done, Wed Sep 30.** Game, oracle, tests, generator, balanced data, endpoint client, eval script, Colab commands. Kev data/API formats verified from source.

**Day 1, Thu Oct 1: Colab and the base model.**
- Colab Pro, L4. First cell: `torch.cuda.is_bf16_supported()` must be True.
- `pip install uv`, clone Kev, `uv sync --extra serve`. Mount Drive, all outputs under Drive.
- Data format already verified against `kev/data.py` (state may be a plain string; every question needs `type` and `label`; `choice` needs `criteria`, `noul` does not). `kev.train --data`, `kev.benchmark --data` and the `/v1/systemone` response shapes verified too. Commands are in `colab/train.sh`.
- One thing to check on the Hub before training: that `--base` in `colab/train.sh` matches the base model `jaredpalmer/kev-0.8b` was trained on (its `training_config.json`).
- `kev.benchmark --run jaredpalmer/kev-0.8b` on `eval.jsonl`. Record the zero-shot row.
- Write `model/client.py` against `kev.serve`, run `play.py --policy model` with the base checkpoint, 200 jumps. Record win rate. Record a 20-second terminal clip of it dying.

**Day 2, Fri Oct 2: train.**
```
uv run python -m kev.train --data train.jsonl --init_from jaredpalmer/kev-0.8b \
  --epochs 2 --lr 5e-5 --batch 4 --accum 2 --dtype bf16 --device cuda --out runs/skyfall-0.8b
```
- Benchmark. If `move` < 90%: 3 epochs, then 40k examples, then 4B on A100 with `--batch 1 --accum 8 --checkpointing 1`.
- Checkpoint to Drive.

**Day 3, Mon Oct 5: play and the twist.**
- Fine-tuned model plays 200 jumps, with and without `--surprise`. Fill the table.
- `play.py --policy model --show` prints P(left/right/stay) and P(open) per tick. Record the clip.
- Optional: time 100 decisions through Kev vs a general LLM with structured output. One number each.

**Day 4, Tue Oct 6: slides and dry run.** Timed, cut to 25 minutes.

**Day 5, Wed Oct 7: buffer.** Clean-Colab rerun from the README.
